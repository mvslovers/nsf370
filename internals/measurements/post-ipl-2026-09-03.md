# Post-IPL baseline, 2026-09-03 — the clean-stand CSA reference for M5-2(e)

**Taken in the window immediately after Mike's IPL of `mvsdev`, before any
client ran.** These figures belong to **M5-2(e)**, whose run discipline locks
*"a clean machine. The free block, before and after. No retained anchors going
in."* They are deliberately **not** in `docs/measurements/m5-2e/`: they were
taken before (e) started, and filing them under (e) would misdate them.

Nothing here is a gate and nothing flips. This is a reference reading.

---

## 1. What was actually captured, and what could not be

**The reading:**

```
FFFF  7.01.29 STC 1767  NSF055I CSA POOL 137272 BYTES (64 SLOTS X 2144)
                        -- LARGEST FREE BLOCK NOW 1073152
```

**This is the POST-pool figure**, and that is not a detail — it is the whole
of what the number means. `nsfsx_csa_largest()` has **exactly one call site**,
`src/nsfsx.c:559`, and it runs **after** `nsfsx_anchor_alloc()` has already
taken the 137272-byte pool. So `NSF055I` can only ever report what is left
once NSF has had its share.

### The kickoff asked for a figure nothing produces

The instruction read, verbatim:

> "`LARGEST FREE BLOCK` immediately after IPL, before `S NSFS`. This is the
> reference figure and nothing else can produce it."

**Measured from source: no instrument in this tree produces a pre-pool
figure.**

- `nsfsx_csa_largest` is startup-only and post-alloc (above). It is not
  reachable from any MODIFY verb — `F NSFS,STATS`, `F NSFS,DISPLAY` and
  `F NSFS,APPS` do not call it.
- `src/nsfv.c` (the probe STC) has no equivalent at all — it emits no
  free-block message, so starting NSFV instead does not help.
- `test/mvs/tstmvcd.c` **does** run a doubling `SP=241` search, but it is
  **capped at 1048576 and reports powers of two**, so on a stand whose true
  figure is 1073152 it returns `1024 KB [search capped]`. Not comparable with
  `NSF055I`, and running it costs a TESTLIB replacement plus a #53 failure.

**No derived "before" figure is recorded here.** `after + 139264` is arithmetic
with empirical support on this stand, not a measurement: the pool need not be
carved from the largest block, and (e) has no use for the number anyway — every
comparison in the record is against the clean-machine **post-pool** value.

### Consequently items 1 and 2 collapse into one reading

The kickoff's item 2 ("`LARGEST FREE BLOCK` after `S NSFS`") is the same
`NSF055I`. There is one reading per start, and it is the post-pool one. A
second reading is available only from a second start — see §4.

## 2. No retained anchor was inherited — and the check is a known value

On a clean IPL nothing *can* be inherited: CSA is rebuilt at IPL, so recording
the anchor and router EP is a **forward comparison baseline**, not a detection.

The detection that does exist is stronger, because it has an expected value:
**`LARGEST FREE BLOCK NOW 1073152` is exactly what every prior clean start on
record reports** (64-3-1 `stageA-console.log`, 64-0e, 64-0f, 40-chk). A stand
carrying one retained anchor reads 933888; two reads 794624. It read 1073152.

| | value |
|---|---|
| STC | 1767 |
| `NSF041I` anchor | `00A8B7C8` |
| `NSF041I` wake ECB | `000BE814` |
| `NSF042I` router EP | `00A820C8` |
| `NSF055I` largest free block (post-pool) | **1073152** |
| pool | 137272 = 64 slots × 2144 |

Corroborating context: `D A,L` before the start showed **6 jobs, 3 initiators**
— JES2, NET, TSO, UFSD, FTPD, HTTPD — and no NSFS/NSFV/NSF of any kind. The
console log was 336 lines (a freshly IPLed system).

## 3. Two things in the same capture that are NOT about CSA

**(a) The CTCI pair did not come up.**

```
NSF202E CTCI 0500 ALLOC FAILED S99 ERR 0244 INFO 0000
NSF212E CTCI 0500 FAILED TO START
```

`ssh mvsdev "ip addr show tun0"` answers **`Device "tun0" does not exist`** —
Hercules did not create the TUN at IPL. This is the environmental shape m5-79
hit and recorded: MVS IPLs without 0500/0501, 3.8j has no dynamic I/O
reconfiguration, and **only a full Hercules restart recovers it** (`devinit`
must NOT be used — it opens a second `tun` at the same address with a competing
route).

**It does not invalidate the CSA figure**, and the reason is structural rather
than a judgement call: the pool is CSA (`SP=241`), while the CTCI driver's
pools are NSFMM regions in the **private** region. The device alloc also fails
*before* the pool is taken, allocating nothing. The value matching every
device-up clean start on record (§2) is the empirical half of the same point.

It does mean **any (e) arm needing the wire needs a Hercules restart first.**
`TSTRQXC` does not — its verb is side-effect-free with `ubuf = NULL`.

**(b) The `getmain ... failed, rc=0x04` lines are expected noise.** Seven of
them precede `NSF055I`. They are `nsfsx_csa_largest`'s own doubling-then-refine
search: libc370's `getmain()` WTOs on every failed GETMAIN, and the search
*ends* on a failure by construction. `test/mvs/tstmvcd.c` carries the same
warning for the same reason. They are not an error.

## 4. The second reading, and what it is worth

Taken after this round's TSTD1B run, on a `P NSFS` / `S NSFS` cycle — see
`docs/measurements/m5-d1b-rolea/`. A second `NSF055I` equal to the first is a
free leak check: it says the first instance gave its CSA back, i.e. the run
left no retained anchor. It is not an independent measurement of anything else.

**Result: `LARGEST FREE BLOCK NOW 1073152`, identical**, and on the **same
anchor `00A8B7C8` and the same router EP `00A820C8`**. The stop was clean
(`NSF043I SVC 239 RESTORED`, no `NSF054W`). The address equality is the
stronger half: a retained anchor forces the next start onto a *different*
address, which is how 64-1 and b4 identified retention. So the stand is still
at its post-IPL baseline, and the reference in §2 continues to describe it.

## 5. What this does NOT establish

- Any pre-pool free-block figure (§1 — nothing produces one).
- Anything about CSA **total** (2064 KB, measured by b0 through
  `CVT → CVTGDA → GDA+8 CSAPQEP → PQE+20 PQESIZE`); this is the largest
  **contiguous** block, refined only to 4 KB, so it carries ±4 KB.
- That the stand stays clean: it stays clean only until something retains an
  anchor. An `NSF054W` on any (e) run discards that run.
- Anything about `#64`, `#67`, `#88` or `#92`, all of which remain open.
